# Phase 1 — UI Design Contract

> Visual and interaction contract for the Production Model Gateway phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** new `/settings` page (gateway CRUD + test connection), agent creation flow change (`gatewayId` + free-text `model`), and 5-class gateway error presentation (inline bubble + top-of-room banner).

**Locked upstream (do NOT re-ask):** D-01..D-13 from `01-CONTEXT.md`; sketch findings (`sketch-findings-councilkit`); existing token system in `src/styles/globals.css`; existing `ui/*` components (`Button`, `TextInput`, `Select`, `Textarea`, `Modal`); Tailwind 3 dark built-in.

## Spacing Scale

8-point scale (multiples of 4). Aligned with sketch findings (`padding: 20px`, `page-body 28px`, `gap: 12-14px`) and existing code (`px-3 py-2`, `gap-1/2/4`, `max-w-2xl px-6 py-8`).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon-text gap, badge internal padding |
| sm | 8px | Compact element spacing, agent config card internal gap |
| md | 12px | Nav item icon-label gap, list-item gap |
| lg | 16px | Default element spacing, form field gap, list-item padding-y |
| xl | 20px | Card padding, nav-item padding-x (sketch-locked), gateway card padding |
| 2xl | 24px | Section padding |
| 3xl | 28px | Page body padding (sketch-locked) |
| 4xl | 32px | Layout gaps between page sections |
| 5xl | 48px | Major section breaks |
| 6xl | 64px | Page-level top/bottom spacing |

**Authorized scale (record for executors — do not second-guess):** project's authorized extended scale = `{4, 8, 12, 16, 20, 24, 28, 32, 48, 64}`, 9 values, all multiples of 4. Extensions beyond the canonical 7 `{4,8,16,24,32,48,64}` are: **12px** (aligns with existing `px-3`/`gap-3` utility usage), **20px** & **28px** (`sketch-locked`, per `sketch-findings-councilkit`). No other spacing values are permitted in Phase 1 code (every `gap-*`/`p-*`/`m-*`/inset must map to this scale; forbid arbitrary pixel values).

**Exceptions:** minimum touch target 32px (h-8) for icon-less inline buttons is acceptable in this desktop-first local-first tool — minimum 40px (`h-10`) required only for the gateway **测试连接** primary action and **保存网关** primary button to reduce misfires. Sidebar collapse toggle is 28px (matches existing `p-2` button).

## Typography

System-ui, dark theme. 4 sizes, 2 weights (regular + semibold) per template; avatars reuse semibold for initial glyphs.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm leading-relaxed font-normal` |
| Label / meta / badge | 12px | 400 (regular) | 1.4 | `text-xs leading-snug` |
| Section heading | 16px | 600 (semibold) | 1.3 | `text-base font-semibold` |
| Page title | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |

**Exceptions:**
- Agent/gateway avatar initial glyph: 12px at weight 600 (matches existing `AgentConfigCard` h-6 w-6 `text-xs font-medium`; upgrade to `font-semibold` for consistency).
- Inline error banner headline uses 14px @ semibold to distinguish from body.
- Brand wordmark "CouncilKit" in sidebar header: 14px @ semibold, `tracking-wide` (preserves existing).

Weights in use: **400 + 600 only.** Do not introduce 500 or 700 in new Phase 1 code (existing `font-medium` on Avatar is the one legacy occurrence — leave it OR upgrade to `font-semibold`; do not add new `font-medium`).

## Interaction Flows

### Visual focal point (/settings primary screen)
**Primary focal unit:** the gateway list cards — each card is the most visually weighted element (semibold name + status pill + accent-on-hover border), drawing the eye first. **Secondary anchor:** the `+ 添加网关` top-right accent button. The test-connection button's transient success/error pill is the only element that may momentarily override focus (state change, settles back). Hierarchy is reinforced by type scale (20px title → 16px section → 14px card name → 12px meta), 60/30/10 color, and single-accent CTAs.

### /settings — gateway CRUD

1. **List view:** page title 「设置」 → section 「模型网关」 with description → gateway list (cards, `bg-surface border-edge rounded`, padding `lg` 16px, gap `sm` 8px between items) → each card shows: gateway name (14px semibold) · type badge (12px `bg-surface-2` pill) · baseUrl (12px mono `font-mono`, muted) · defaultModel (12px muted) · status pill (test-connection state) · actions on right: `测试连接` · `编辑网关` · `删除` (red ghost).
2. **Empty state:** centered `EmptyState` component (`src/components/shared/EmptyState.tsx`) with heading + body + CTA.
3. **Add flow:** click `+ 添加网关` → opens existing `Modal` → form fields (section above) → 「保存网关」 validates non-empty (name, type, baseUrl, apiKey) → `testConnection` is **not** auto-run on save; user may click 「测试连接」 any time after save.
4. **Edit flow:** click `编辑网关` → same Modal, prefilled → apiKey field shows `••••••••` masked placeholder (leave empty to keep existing; typing replaces). Save preserves existing cipher if apiKey field untouched.
5. **Delete flow (destructive):** click `删除` (red ghost text) → confirmation Modal: `删除网关「{name}」？` + body `该网关下 {N} 个 agent 的 gatewayId 将被清空并标记为离线。密钥将从本机删除。此操作不可撤销。` + `[取消] [删除]` (delete = `bg-error text-white`).
6. **Test connection (D-08):** click `测试连接` → button enters `testing` state (disabled,「测试中…」) → fires minimal stream request (`gateway.defaultModel`, `max_tokens=1`, `stream:true`) → on HTTP 200 + ≥1 delta: pill → success「已连接」, button → 「已连接」 (disabled, success tint). On error: pill → failed (`密钥无效` / `连接失败`), button → `重试测试`; show inline error text below the card.
7. **Responsive:** page uses existing `mx-auto max-w-2xl px-6 py-8` pattern (consistent with `NewRoomPage`).

### Agent creation flow change (NewRoomPage modal)

1. Modal title `添加 agent`. Fields: 角色/立场 (TextInput) → 网关 (Select, options = current `gateways` from Dexie) → 模型 ID (TextInput, value initializes from selected gateway's `defaultModel` when gateway changes; user may override).
2. If `gateways.length === 0`: replace gateway Select + model TextInput with notice block (`bg-warn/10 border-warn text-fg rounded p-lg`) `尚未配置任何网关…` + `前往设置` link. Confirm button disabled.
3. Existing color auto-assignment (`COLORS[agents.length % COLORS.length]`) preserved.
4. Agent list below modal (`AgentConfigCard`) — update subtitle from `{agent.model}` to `{gateway.name} · {agent.model}` (requires `AgentConfigCard` to look up gateway by id; pass `gatewayName` prop).

### Error propagation flow (runRound integration, D-09..D-12)

1. `dispatchStream` returns `AsyncIterable<string | GatewayError>`; `runRound` collects errors per agent.
2. Fatal (`invalid_key`): set gateway-level offline flag → all queued agents with same `gatewayId` skip with inline `网关已离线` message; do NOT fire their requests.
3. Recoverable: only that agent goes `offline-{kind}`; remaining agents proceed (sequential `runRound` already supports).
4. End of round: if any agent succeeded → normal summary. If all agents offline → skip summary, post top-of-room banner `本轮无有效发言，未生成总结。` (warn), mark round `completed` without summary.
5. Inline error renders inside the agent's existing message slot in `DiscussionStream` (extends `MessageBubble` with an optional `error: GatewayError` prop, or appends a system-message bubble).

## Responsive & A11y

- Desktop-first (local-first single-user tool). Sidebar 260px (existing); main area reflows. `max-w-2xl` content cap preserved on SettingsPage.
- Mobile: sidebar collapses (existing `toggleSidebar`); gateway form Modal should scroll vertically (`max-h-[80vh] overflow-y-auto`) on small viewports.
- All form controls have `<label htmlFor>` (existing `TextInput`/`Select` pattern) — gateway form must match. `aria-label` on icon-less action buttons (`测试连接` has visible text; `×` dismiss on banner needs `aria-label="关闭"`).
- Error banners must be `role="alert"` so screen readers announce on insertion.
- Inline bubble errors use `role="status"` (not alert, since they accompany a known agent slot).
- Color is never the sole status signal: every error tone has a leading `⚠` glyph + text label; status pills always have text.
- Destructive delete Modal: focus moves to `取消` (safe choice) on open; ESC cancels.
- Keyboard: Enter on focused `GatewayCard` opens edit; Delete key shortcut not added (avoid accidental destroy).
