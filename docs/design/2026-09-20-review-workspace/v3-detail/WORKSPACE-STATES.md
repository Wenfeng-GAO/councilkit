# CouncilKit v3 · 固定席位工作台状态映射

用户已选择 exploration-v3 的 01 工作台。本文件将 v2 六种画面的交互语义映射到固定三栏；布局以本文为准，数据与容量契约继承 [v2 交互规格](contracts/INTERACTION-SPEC.md) 和 [v2 交付计划](contracts/DELIVERY-PLAN.md)。图中内容均为示例，不表示能力已上线。

## 1. 固定槽位

| 槽位 | 桌面结构 | 切换时保持的内容 |
| --- | --- | --- |
| 全局导航 | 184px；产品入口与设置 | 不因所选席位或运行状态改变位置 |
| 工作台导航 | 248px；本轮总览、当前修复入口、审查席位、独立 Aggregator 组 | 席位按本轮声明顺序排列；状态变化不重排 |
| 上下文栏 | 主区顶部 48px；PR、审查 SHA、Run 状态 | 只显示真实上下文；长标题截断可查看全文 |
| 视图栏 | 上下文栏下方 48px | 单席：职责＋报告/过程＋当前视图操作；总览/修复：对应标题与必要操作 |
| 主内容 | 弹性宽度、独立阅读区 | 正文、状态、过程只随明确选择变化；阅读位置按身份保存 |

桌面移除席位标题旁重复的切席下拉。所有席位入口复用同一数据选择器与稳定身份；Aggregator 置于独立组，不冒充额外独立审查席。仅在真实修复存在时展示“当前修复”入口，预留位置不放无效按钮。

报告页只持有一个 `selectedAttempt`。本轮总览、当前修复属于 Run 视图；单席报告和过程共用同一个所选 Attempt。不得同时打开另一席位的过程、右侧常驻第二份席位列表，或加入探索方案 3 的底部 console。

## 2. 六状态 × 槽位

| 状态 | 导航选中 | 视图栏 | 主内容顺序 | 数据门槛 |
| --- | --- | --- | --- | --- |
| 01 本轮总览 | 本轮总览 | 本轮审查 | Run 状态/不完整提示 → 已有可靠摘要或账本 → 汇总正文；修复存在时提供独立入口 | A；只展示真实 Run 证据，无单席假计数 |
| 02 完成、原文未结构化 | 对应席位 | 报告选中 | 执行完成、时长、来源 → 中性说明“暂无结构化摘要” → 当前执行报告原文 → 历史过程入口 | B；不画 0 项发现/通过/需要修改 |
| 03 进行中、暂停跟随 | 对应席位 | 过程选中 | 当前动作/最近真实活动 → 保留阅读位置的过程 → “新增 N 条活动 · 回到最新” | A；暂停滚动不等于暂停 Agent |
| 04 席位失败 | 对应席位 | 首次进入报告页 | 执行失败及已记录原因 → 查看过程/复制净化诊断 → 可读取的当前执行资料 | B；不得回退旧成功或从 live 推导结论 |
| 05 历史过程与搜索 | 对应席位 | 过程选中 | 来源/范围 → C 启用后才显示搜索筛选 → 时间顺序活动与匹配定位 | A 提供基本过程；复杂分组、搜索属于 C |
| 06 修复进行中 | 当前修复 | 当前修复 | 原审查引用与 SHA → 真实当前阶段、轮次及更新时间（若有）→ 已生成资料与关联复审入口 | A 使用现有数据；缺字段不补猜测 |

六状态共用固定列位置，主内容替换不打开全屏遮罩。Run 总览的汇总结论必须标明范围；进入 Aggregator 则读取该汇总执行的报告/过程。两处同源，不各自推导结论。

修复页沿用实际后端阶段与操作能力。审查 X/Y 席已结束不能充当修复进度；只有真实关系才能显示复审轮次。未记录耗时/过程时只显示已知阶段，不添加百分比、剩余时间或无依据的持续动画。

## 3. 首次进入、切换与阅读连续性

- 第一次选择运行中席位：默认过程，跟随底部；等待启动/排队席位显示真实状态与等待说明。
- 第一次选择已结束席位：默认报告。success 的全文、空输出、读取错误分别呈现；failure/cancelled 显示相应执行状态，不要求正文存在。
- B 未交付时，A 只承诺“查看进展/查看详情”；不展示假可用的完整报告，也不从 live 启发式提取权威结果。
- 切回已看过的同一执行：恢复报告/过程模式、展开项、稳定阅读锚点与偏移，不再次套用首次进入默认值。
- 阅读过程中席位完成：只更新执行状态并提供“报告已就绪 · 查看报告”；不自动切 Tab、不抢焦点、不移动历史锚点。
- 报告底部“查看历史过程”切到同席位的过程，保存报告位置；Tab 切换不触发 Agent 执行。
- B 的恢复键为 `runId + attemptId + executionRef`；新执行不复用旧结果/阅读位置。A 无可靠 ref 时仅保证当前挂载会话，无法确认代次则重新读取。
- 切席取消后续请求并忽略迟到响应；游标重置时重建相应缓存。仅当前所选席位拉取过程，容量与退避遵守 v2 交付计划。
- “重新读取”只重读数据，不重跑席位。历史版本选择器属于 C，本次不显示。

## 4. 空态与错误态

| 实际情况 | 对应位置及文案 | 保留能力 |
| --- | --- | --- |
| 报告首次读取 | 报告正文区小型骨架或“正在读取报告” | 导航和过程仍可使用；有限重读后给明确结果 |
| success、持久化正文为空 | “执行完成 · 暂无结果正文” | 查看已保存过程；不等同零发现 |
| 报告读取失败/无法确认当前版本 | “报告暂时无法读取”＋重新读取 | 已有过程保留；不用旧成功或 live 正文替代 |
| 运行中、尚无事件 | “等待首条记录” | 真实执行状态与有依据的时长；不造阶段 |
| 已结束、过程响应为空 | “暂无可读取的过程记录” | 报告独立可读；不声称确定未保存 |
| 过程请求失败、有缓存 | “过程读取失败，已保留读取内容”＋重新读取 | 继续阅读，保留锚点 |
| 过程请求失败、无缓存 | “过程暂时无法读取”＋重新读取 | 不展示成“没有记录” |
| 过程截断 | 过程范围处“过程记录已截断，当前展示已保存内容” | 正文仍独立读取；截断不证明执行卡死 |
| 旧过程无法对应当前执行 | “该席位已保存过程 · 版本未单独记录” | 不称为本次执行完整过程 |
| C 搜索无匹配 | “没有匹配的记录”＋清空搜索；相邻标明已保存/已加载范围 | 不与过程缺失合并 |
| Host 不可达 | 上下文区域连接提示与重新连接入口 | 本地已读内容可读；不自动启动 Host |

失败未记录原因时写“未记录详细原因”。未知状态写“状态未知”；已可验证资料仍可阅读。状态始终带文字，执行完成不表示审查通过；所有普通计数使用中性色。

## 5. 响应式与键盘

- `>1120px`：184px 全局导航＋248px 席位列＋弹性主区。
- `901–1120px`：全局导航收为 64px 图标栏，保留标签提示与可访问名称；席位列仍为 248px。
- `≤900px`：席位列收为视图栏内明确的“席位：对抗审查”选择器；本轮总览/当前修复是明确分组，Aggregator 独立。选择器位置稳定，菜单顺序与桌面相同。
- 手机：全局导航收为菜单；先显示 PR/Run 上下文，再显示所选范围和报告/过程，最后正文。长标题与次级元信息换行；48px 栏高可增高，不横向挤三栏。
- 长命令和代码仅在局部横滚，中文正文正常换行；阅读控件和返回最新不遮住最后一条内容。
- 侧栏使用普通导航语义；报告/过程具备 Tab 的选择态与键盘行为。只有弹出菜单管理临时焦点，关闭回到选择器；常驻工作台不设置伪模态焦点圈。

## 6. 验收

1. 五席中一席完成即可读取该席当前 durable 原文；未结构化报告正常排版，无伪造 verdict、发现数或解析等待动画。A 单独交付明确 B 尚未可用。
2. 运行、完成、失败、Aggregator 汇总的状态变动不改变席位顺序与三栏位置；桌面无重复下拉、右侧席位副本或底部 console。
3. 历史中部阅读时席位完成，Tab、焦点、展开与锚点不变；点击报告就绪才切换，返回过程能继续阅读。
4. 同 Attempt resume 后不展示旧成功为当前结果；快速切席的迟到响应无法覆盖当前席位，所有正文与过程标题明确同一所选范围。
5. 分别验证报告空输出、结果读取错误、无过程、过程网络错误和截断；局部失败不清空另一条资料来源，无无限加载。
6. 本轮审查结束但修复仍运行时，两者身份、SHA 与状态分明；审查数量不作为修复进度，真实阶段缺数据时诚实退化。
7. 1440、1024、900、390px 下验证导航顺序、单一选择、正文换行和键盘操作；窄屏切席后阅读规则保持一致，无页面横向溢出。
8. 按 v2 容量计划验证 2 MiB 边界、连续两小时观察、暂停/切席/断网恢复：单席单请求、有界缓存、终态停止轮询；静态设计图不替代实测。
