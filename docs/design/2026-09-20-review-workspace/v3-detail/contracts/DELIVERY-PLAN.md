# CouncilKit 审查工作台 v2：交付与验收计划

日期：2026-09-20。产品源码基线：`3f968a2`。本计划是待实现的工程范围，不表示功能已完成或性能已达标。交互含义以 [INTERACTION-SPEC.md](./INTERACTION-SPEC.md) 为准。

## 1. 三条交付线

| 交付线 | 独立工作项 | 依赖与发布条件 |
| --- | --- | --- |
| **A：界面改善** | A1 审查/修复分区与单份紧凑席位列表；A2 当前活动与跟随控制；A3 阅读连续性、键盘与窄屏适配；A4 容量基线与必要性能修正 | 使用现有接口，可独立于 B 发布。入口及文案不宣称已具备可靠完整席位报告 |
| **B：可靠结果** | B0 当前执行身份语义验证；B1 当前 durable result API；B2 前端结果/未结构化/失败/空态/错误态；B3 真数据联调 | B0 → B1 → B3 是核心链。B2 可基于已冻结契约先开发；B1、B3 未通过前不能宣称“结果优先”已交付 |
| **C：后续增强** | 历史选择器与版本列表；复杂分组搜索；结构化 verdict/finding；跨席位关系与证据定位 | 分项建设生产数据契约再上线，无需阻塞 A/B |

前端 Agent 可以立即做 A；后端 Agent 同时做 B0/B1。B2 使用 fixture 只能验证布局与状态覆盖，**静态 mock 不是 B 验收证据**。若 B 延迟，只发布 A 并明确 B 未交付；不增加 fake verdict、从 live 猜正文或把旧成功结果当作临时兜底。

## 2. B 单独排期的技术关口

### B0：先证明当前执行身份可以成立

提交一份简短映射说明及可运行测试，覆盖：首次运行 → 自动重试 → resume 重跑 → 显式复用 → Aggregator 重跑。验证同一个 `attemptId` 下每次执行可区分，当前执行状态与正文不会错配。

- `attemptNumber` 单独不够；明确 resume 代次/持久化身份如何产生。
- 证明 ref 在原子重写与后续 append 后稳定，并从执行中延续到终态。
- 若旧数据不能恢复身份，说明准确的退化语义；若当前运行在尚未写终态时无法可靠识别，补最小生产端身份事件。不得在前端猜代次。
- 本阶段不做历史版本列表或选择器，不建立无必要的新数据库。

**B0 产物是 B1 的评审前置，不是把身份正确性推迟到后续的借口。** 由后端负责人根据这一步的结论给出 B1/B3 排期；设计不虚构工期。

### B1/B2：最小契约与页面同步完成

API 只读取当前执行的 durable 全文与状态，返回 `executionRef`、可用性、正文、截断标识、已记录失败、显式复用来源。前端正常展示没有结构化摘要的可读报告；失败面板展示原因与过程，不生成审查结论。

保留当前读取边界与认证约束；结果读取错误不能影响过程可读性。历史浏览、解析 verdict、精确过程版本映射不混入本期范围。

### B3：真实读取链验收

使用真实 Host 读取由 CLI 写盘或通过 CLI transcript writer 构造的合法文件，验证结果 API 和浏览器端到端链路。fixture 不能绕过 durable 读取接口；至少一例来自真实审查运行。无需为每个异常场景付费调用模型。

## 3. 容量约束：先明确已有保证

现有 live writer 默认约 **2 MiB/席位文件**，写一次截断事件后停止正常追加；非 delta 边界记录与截断标记可能略超阈值。因此不能把风险描述为“单席保存数据随运行时间无限增长”。

实际需要验证的是：JSON 字符串转对象与 DOM 后的放大、重复数组/派生结构、切席缓存、计时器泄漏，以及 Host 每次轮询的同步全读全解析。当前 `afterSeq` 只减少响应事件，不保证服务器按磁盘增量读取。长运行即使文件不再增长，重复解析与空轮询仍可能持续消耗资源。

### 3.1 首期硬性行为约束

- 同一所选席位同一时间最多一个 live 请求；失败重读与定时轮询不能叠加请求。切席/关闭取消后续轮询，旧响应不能落到新席位。
- 活跃前台默认沿用 2 秒轮询作为起点；响应未返回不启动第二次。错误采用有上限的退避；隐藏页面降低频率或暂停，恢复时从正确游标续读。终态停止常规轮询，手动重新读取仍可用。
- 暂停跟随期间数据保留策略必须有界：原始事件缓存按席位/字节数限制并淘汰，阅读状态仅保留锚点等小型元数据。淘汰后可以重新读取磁盘已保存内容，不能静默丢失或声称仍在搜索全文。
- 原始事件、折叠活动、搜索索引不得无限保留重复副本。缓存上限、淘汰规则与重读行为在实现 PR 中给出；不得仅写“2MB 很小所以没问题”。
- 过程行数增长不能导致 DOM 与全部源事件一比一永久增长；先测基线，必要时用窗口化或分段展示。大文本展开也要测，不能只限制行数。
- 空轮询不得重新复制全部事件、重建全文或触发全量列表重渲染。追加/去重应只处理新数据；不要每次追加对全部序号做二次复杂度查找。
- 完整报告与过程分开读取、缓存和计量。过程 2 MiB 上限不能当作报告正文上限；报告若受限制必须如实标明，并补全文可读路径才能通过 B。

### 3.2 数值预算的建立方法

下面是**候选工程目标，不是已经测得的保证**。实现前先在约定开发机、固定 Chrome 版本和生产构建下记录基线，A4 中固定预算；如不可达，提交瓶颈与修正方案后显式调整，不能在交付时悄悄删掉指标。

| 指标 | 首轮候选目标 | 测量方法 |
| --- | --- | --- |
| 2 MiB sidecar 首次打开 | 报告页已有壳体后，过程首屏可交互 ≤ 1 秒 | 浏览器 performance marks，冷/热各 10 次，记录 p95 |
| 追加记录、暂停/恢复、切席 | 用户操作至可见反馈 p95 ≤ 100 ms；常规追加不产生 > 50 ms 主线程长任务 | PerformanceObserver + 录制代表性 trace；排除首次 Markdown 解析后仍报告其单独成本 |
| Host live API | 单请求 p95 ≤ 150 ms；累计读取/解析 CPU 随轮询频率可解释 | 记录请求耗时、文件字节/事件数、Host CPU；测 1 个与 3 个同时打开的观察页 |
| 时间线 DOM | 一次挂载的活动行目标 ≤ 200（含 overscan），固定壳体另计 | 记录活动行数与总 DOM 节点；长文本额外观察布局/高亮成本 |
| 暖机后内存 | 2 小时后回到同一席位、同一视图，GC 后 retained heap 比暖机基线增长 ≤ 20% 或 10 MiB（取较大值） | 暖机后及 30/60/120 分钟堆快照，比较持有者；同时报告绝对峰值，不能用此增量预算掩盖巨大初始堆 |
| 后台/空轮询 | 隐藏页面请求数明显下降；无数据追加时无全量折叠/渲染 | 统计 10 分钟网络、组件提交与折叠次数 |
| C 的本地搜索 | 停止输入后 p95 ≤ 150 ms 出结果；不阻塞跟随控制 | 2 MiB 高密度与长文本 fixture，各测中文/路径/无匹配字面量；C 实现前重设基线 |

若采用固定缓存预算，可先评估“当前席位 + 最近一个席位”的原始事件缓存策略；不要把 8 席全部展开并常驻作为默认。具体 MiB 预算依据对象放大实测确定，必须同时列出原始字节与 JS 堆开销。视图恢复优先保留小型锚点元数据，不要求保留全部完整对象。

## 4. 功能验收

| 场景 | 预期结果 | 归属 |
| --- | --- | --- |
| 审查已结束，pipeline 仍在修复 | 首屏分开显示本轮审查与当前修复；X/Y 审查席位不作为修复进度 | A |
| 列表状态持续变化与快速切席 | 席位列只有一份列表；所有席位入口同源同序，不跳排；迟到响应忽略 | A |
| 滚到历史中部，席位随后完成 | 阅读锚点、焦点、展开状态不变；只提示报告就绪，点击后才跳转 | A+B |
| 暂停时连续文本 delta | 新活动数按稳定活动行计数，不按字符增长；不自动滚动 | A |
| 5 席仅 1 席完成 | 立即读取该席当前 durable 全文，无需等待 Aggregator | B |
| success + 普通自然语言报告 | 中性正常阅读态，完整报告在前；无假 0 项发现/通过结论 | B |
| failure + live 末尾含 approve | 显示执行失败与已记录原因，保留过程；不生成审查通过 | B |
| 过程缺失或已截断，最终正文完整 | 正文仍完整；过程范围提示准确；不以 live 可用性决定结果存在性 | B |
| 同 Attempt 先失败再重试成功 | 当前 ref 对应本次成功；无需历史选择器即可证明不返回前次错误正文 | B |
| 旧成功后 resume 当前仍运行或失败 | 不返回旧成功为当前结果；显式复用的席位才标注复用来源 | B |
| 原子重写、追加新记录、目标记录超过摘要扫描 cap | 已有 executionRef 含义稳定；目标全文可读取，不伪装为空 | B |
| 网络断开后恢复，多次点击重新读取 | 不出现并发轮询累积；按游标去重续读，缓存与阅读位置保留 | A+B |
| 终态空输出、损坏结果、暂时未落盘 | 分别显示空态、读取错误、有限等待；不会永久加载或从 live 补造正文 | B |
| 长路径、HTML/脚本内容、窄屏与键盘 | 安全渲染，无横向溢出；关闭回原入口；状态不用颜色单独表达 | A+B |

## 5. 容量与两小时 soak 验收

采用合成回放控制时序，并通过真实 Host/API/浏览器读取，避免用模型长跑充当性能测试。保留至少一个真实运行样本用于确认格式代表性。

| 场景 | 测试操作 | 必须观察与记录 |
| --- | --- | --- |
| **高事件密度 2 MiB** | 生成大量小 delta、交错工具事件、坏行和末尾未完成行；从空文件逐步写到截断边界 | 事件去重成本、API p95、首屏/追加耗时、DOM 数、堆放大、截断提示；坏行不致崩溃 |
| **长文本 2 MiB** | 少量很长 text/thinking 块、长路径、Markdown 代码块；展开、复制、切席 | 排版和语法高亮成本；复制范围诚实；折叠后释放/复用策略；正文与过程独立 |
| **边界与终态** | 恰低于上限、跨上限、截断事件、截断后仍 running、随后完成 | 不丢截断提示、不反复追加标记、不伪称卡死；完成后停止轮询，B 全文不受 sidecar 截断影响 |
| **2 小时持续观察** | 达到产品人数上限的合法 Run（以实际约束为准，不重复计算 Aggregator）；仅选中席位拉流；有的早满 2 MiB，有的稀疏更新；每 15 分钟切席，含 20 分钟暂停跟随、10 分钟隐藏、断网恢复 | 0/30/60/120 分钟堆与 DOM；累计网络/CPU；缓存上限与淘汰；返回旧席位锚点；无计时器/监听器累积或不断增加的重复事件 |
| **恢复与代次切换** | 暂停时发生 resume 或序号重置，再恢复可见与网络 | 不继续沿用失效游标，不混入旧结果，无法映射过程时文案保守 |
| **C 搜索负载** | 在上述两种文件上持续输入与切筛选；后台仍追加 | 搜索 p95、索引内存、命中稳定性；暂停期间不抢焦点或跳转；截断范围明确 |

2 小时不是必须持续增长两小时；文件达到上限后的空轮询、缓存寿命和视图切换也是重点。若使用时间加速测试，不能代替一次真实两小时 soak；两者在回执中分别标记。

## 6. 交付回执

每条交付线给出：实现 commit、实际能力、尚未完成项、功能场景证据和容量测量结果。A 可先验收；B 必须附 durable 真实读取与版本映射证据；C 按功能单独验收。

容量回执至少包含机器/浏览器/构建模式、fixture 字节与事件数、轮询策略、缓存预算、DOM/堆/CPU/API 延迟、两小时前后对比及 trace/截图路径。没有实测数字时写“未验证”，不能因为已有 2 MiB 上限就标“性能通过”。

不为静态样式写镜像测试。优先测试身份映射、真实结果来源、异常语义、重复/迟到响应、完成时阅读连续性与长会话资源行为。
