# CouncilKit 审查工作台 · 视觉与页面规格

本文件与 5 张高保真 PNG 配套。目标是前端可实现的清晰规范；所有数值单位为 CSS px。设计图中演示数据、图像生成的细微差异和不具备真实接口的入口，按本文件与 INTERACTION-SPEC 处理，不直接照搬到生产界面。

## 1. 视觉方向

沿用 CouncilKit 的深色、暖白与黄铜色。主要变化是内容主次、阅读宽度与信息密度；不改变全产品品牌。页面以背景和分隔线组织内容，席位和发现采用列表，避免每行一张大卡片。

保留现有词标，不为实现设计图额外制作新 logo。图标使用项目已有方案或统一的轻量线性图标；不能用 emoji 代替操作图标。主操作和选中态用黄铜色，普通链接用蓝色。按钮实色，背景纯色，不复刻图片可能产生的柔光、渐变或纹理。

## 2. 颜色与字体

机器可读值见 [design-tokens.json](design-tokens.json)。

| 角色 | 色值 | 使用边界 |
| --- | --- | --- |
| 页面背景 | `#0b0d10` | 主要阅读区域 |
| 侧边栏/当前动作表面 | `#15181d` | 需要分组的少数区域 |
| Hover/选择底色 | `#1e2128` | 控件与活动行 |
| 分隔线 | `#232830` | 1px；输入/焦点边界必要时增强 |
| 主文字 | `#e6e8ec` | 正文、发现标题 |
| 次级文字 | `#a0a6b0` | 本工作台局部覆盖；不要求全局替换原 muted |
| 暖色标题 | `#efe4cf` | 页面与章节标题 |
| 黄铜色 | `#c4a574` | 主按钮、当前席位与导航选中态 |
| 绿色 | `#22c55e` | 执行完成，或有明确依据的无异常状态 |
| 红色 | `#f85149` | 需要修改、致命、执行失败；必须搭配文字区分 |
| 琥珀色 | `#d29922` | 重大/警告类强调 |
| 蓝色 | `#58a6ff` | 运行中、普通链接 |
| 焦点轮廓 | `#6366f1` | 沿用现有全局键盘焦点 token |

正文系统无衬线，代码/时间/路径使用现有 `--font-command`。不依赖远程字体请求。标题可沿用现有品牌标题字体，但中文需有清楚的系统回退。

| 文本 | 字号/行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 28/36 | 600 |
| 主结论 | 32/40 | 600 |
| 章节标题 | 20/28 | 600 |
| 正文、发现标题 | 15/24 | 400；发现标题 600 |
| 次级信息 | 13/20 | 400 |
| 代码、时间、路径 | 13/20 | 400 |

图片中的标题可能被生成得更大，正式实现以上表为准。核心内容不使用 10–11px 字号。严重性、状态不能只依赖颜色。普通席位发现数字统一为主文字色，不按数量大小决定红/黄；严重性另用带名称的标签。

## 3. 布局与响应式

设计基准 1440 × 1024。PNG 导出尺寸 1487 × 1058 是图像文件尺寸，不能作为页面 CSS viewport。保持自然响应式，不整体缩放截图或应用。

| 宽度 | 布局 |
| --- | --- |
| ≥1280 | 左侧导航 208；主内容左右各 40；列间距 32；结果页右栏 280；正文尽量不超过 800 |
| 1024–1279 | 主边距 24；右侧目录收起为目录按钮；实时席位列表缩至 240；必要时折叠全局导航 |
| 768–1023 | 使用现有可折叠导航；主区单列；席位导航可横向滚动，选中项自动保持可见 |
| <768 | 全局导航收为菜单；主边距 16；标题 24/32；席位选择改为可访问的选择器/横向导航；结果、当前动作、过程顺序不变 |

间距使用 4/8/12/16/20/24/32/40/48/64。页面段落间 24–32；普通行内间距 8–12。按钮和输入框高 40，圆角 6；席位行至少 64；主要可点击区域至少 40 × 40。代码长行可局部横向滚动，路径正文可断行，不能把全页面撑出横向滚动。

正文让中文每行保持约 32–44 字的舒适阅读长度，宽屏下用目录或留白消化余宽。右目录 sticky 在主内容区域，不与页面 sticky 头部重叠。移动端底部操作考虑 safe-area，不能遮住最后一条记录。

## 4. 五张图的落地规则

### 01 审查总览

- 头部：PR 标题、真实 Run、审查 SHA、执行状态、PR 链接、报告操作。
- 主信息：汇总结论与覆盖完整性。运行完成和需要修改可以同时显示，含义不同。
- 发现区域：默认按严重性排序；同级按稳定规则保持位置。折叠其余问题时必须有展开入口。
- 右栏：紧凑席位结果，显示职责、执行状态、可用发现数、查看结果入口。席位计数可重叠，不相加成独立问题数。
- 本图仅展示已完成且解析成功的理想状态；没有结构化发现时用完整报告阅读承接，不伪造列表。
- “查看阻塞问题”仅在真实账本有 `blocksDelivery` 或等价明确字段时使用。严重性高不自动等于阻塞。如果只有严重性排序，正式文案改为“查看优先问题”。
- “开始修复”保留现有 fix 行为范围。在操作旁/现有动作说明中明确“会修改代码并推送，随后复审”；不能把整个流程简化成无副作用的阅读按钮。
- 图中的“导出报告”实现为下载已有 Markdown；若当前仅有复制能力，先保留“复制报告”并据此调整图标，不能放无响应按钮。

### 02 已完成席位

- 本图表示全宽阅读模式。允许由原有席位面板进入“展开阅读”，保留原入口；无需强制新建一套独立路由。
- 顺序固定：执行信息 → 独立结论（有明确来源才展示）→ 发现 → 完整原文 → 历史过程。
- 席位结果与历史页都必须补齐图中简化的上下文：**Run、审查 SHA、执行版本**。可放在次级行和版本菜单中，当前版本明确标记。
- 可靠 verdict 缺失时，标题区域使用“执行完成 · 3 项发现”等，不使用图中“需要修改”。若计数也不可靠，显示“结果未解析”，仍展示原文。
- 右目录仅包含真实存在的章节。无可靠逐条 finding 时隐藏“审查发现 3”锚点，保留报告锚点。
- “查看汇总如何处理这些发现”属于后续证据/采纳映射能力；没有可靠关联时改成普通“查看汇总报告”，不暗示能精确定位。
- 历史过程首次折叠，点击展开时在原位显示摘要时间线；“展开阅读”可进入 04 的聚焦模式。

### 03 审查进行中

- 五席位进度图示只是各席状态列表，**不是串行步骤**。实现时取消五席位之间的连接线；保留各席图标与完成计数即可，防止暗示按顺序执行。
- 当前动作使用真实工具/进展信息；无法可靠命名为“执行重放回归测试”时显示实际工具名和保留的命令摘要。
- 本图在跟随模式；暂停模式的底部条改为“已暂停跟随 · 新增 N 条活动”，按钮改为“回到最新”。N 按稳定活动行/分组统计，不按 token delta。
- “仅看关键进展”只显示有依据的进展文本与确定性分组；不调用模型补写过程结论。
- 现有等待/无事件、读取失败、截断和结果就绪提示沿用同一容器；不要通过清空历史实现状态切换。
- 图里的“展开阅读”扩展当前席位过程宽度，不触发 Agent 或改变任务。

### 04 历史过程

- 本图代表历史过程展开后的阅读模式，与 02 属于同一席位内容；返回时恢复原来的报告位置。
- 默认展开进展与少量工具组，其余按规则折叠。必须为折叠行提供 chevron 与可访问状态，不能只靠图标猜交互。
- 分组只使用真实事件与可确认路径；没有去重文件列表时显示“读取 6 次”，不声称“6 个文件”。
- “调用结束”只表明有结束事件，没有 exit code 或测试结果时不显示“通过”。
- 当前过滤范围是已保存内容；无匹配状态为“没有匹配的记录”，提供清空搜索。没有过程记录是不同空态。
- 图里的“独立意见：需要修改”与来源门槛同 02；数据不足时上下文条显示“执行已完成 · 查看报告”。
- 记录概况在窄屏收进折叠区域。时间戳保持等宽，但文字优先阅读，时间不是最强视觉元素。

### 05 修复进行中

- 图中上方结论属于旧的审查证据，下方属于当前修复活动。开始修复后，上一轮结论不改成成功/通过。
- 阶段标签按真实枚举：`planning` → 起草方案；`plan-review` → 方案陪审；`plan-aggregating` → **汇总方案**；`applying` → 落地；`re-reviewing` → 复审；`done` → 完成。**图中的“锁定共识”正式实现改为“汇总方案”**，不能仅据聚合阶段推断达成一致。
- 图中的独立修复 Run ID、计时和 17:01/17:03 活动记录是演示。存在真实字段才显示；没有开始时间不能从 `updatedAt` 倒推已运行时间，没有子 Run 则不编造 ID。
- “查看修复过程”只能进入真实修复 Run/Attempt；没有可读过程时替换为“等待首条修复记录”，不能打开旧审查过程冒充。
- “尚未进入代码修改阶段”只有当前权威阶段与历史记录支持时才出现；无法确认则显示“当前阶段：起草方案”。
- 状态列有失败/等待/需用户动作时优先展示对应原因。不能持续动画假装仍执行。

## 5. 内容、数字与生成图校正

图中数据均为 demo。测试 fixture 建议固定：5 席成功，独立计数分别 2/1/3/3/2；Aggregator 去重后 7 项，分别 1 致命、2 重大、3 次要、1 建议；对抗席位 3 项，1 致命/1 重大/1 次要。实际应用不固定席位数量、职责名、模型或数字。

“兼容性审查”只是示例职责，真实席位展示配置名称；不把 `review-cursor` 强制重命名为兼容性审查。

01 图中第三条空文本完成帧问题的来源文字应以真实 finding 为准；demo fixture 约定为“正确性审查提出”。图里出现的“独立验证”只是示意，只有明确验证证据时展示；其余情况只标提出席位。切勿把图片中的行号当成可点击代码依据。

所有来源、计数、日期、SHA、工具名、角色名都必须来自生产数据；`演示数据` 仅限展示样例与测试，不进入真实 Run。

## 6. 微交互与可访问性

- Hover/焦点/选中须能区分；过渡约 150ms，`prefers-reduced-motion` 关闭非必要动画。
- 席位 Tab 提供方向键切换与焦点管理，完整标签可见或有可访问名称。关闭面板后焦点返回入口。
- 折叠区域使用原生 details 或等效 `aria-expanded` 控件。搜索有 label，图标按钮有名称。
- 使用 `aria-live=polite` 简短通知状态/新增条数，不把逐 token 文本反复读给屏幕阅读器。
- 默认不平滑滚动每个 token；跟随在内容更新后定位末尾即可。暂停时绝不滚动。
- 实现时实际测量文字和控件对比度；本包设定目标为普通文字 4.5:1、非文字控件 3:1，尚不构成 WCAG 合规结论。

## 7. 视觉验收

至少保存完成总览、单席结果、运行跟随、运行暂停、历史检索、修复进行中、结果缺失/错误的实现截图。覆盖 1440、1024、390 三种宽度。

以本包图的层级、分区、色彩和列表密度作为参考，对数字规格精确落地；不要求复制生成图的微小像素差异。验收必须核对实际接口状态，不只看截图。行为用 INTERACTION-SPEC 的验收案例验证。
