# CouncilKit 审查工作台 v2：交互与数据契约

日期：2026-09-20。源码核对：`3f968a2`，工作区产品实现与旧设计核对基线一致。本文替代旧版交互规格，覆盖 `kind=review` 的报告页、席位详情与过程阅读。分期和验收责任见 [DELIVERY-PLAN.md](./DELIVERY-PLAN.md)。画面只能使用本文允许的真实状态。

## 1. 首期体验与边界

进行中先回答“现在做什么、最近何时有活动”；执行结束后先提供当前执行的可靠报告，再提供历史过程。执行完成、报告可读、结构化结论可用是不同事实。

- **A：界面可独立交付。** 审查与修复分区、紧凑席位列表、当前活动、跟随控制。使用已有 API，与 B 并行。
- **B：核心结果能力。** 单独建设当前执行身份与 durable 全文读取接口，并接入完成、未结构化、失败、缺失和读取异常态。B 通过真实数据验收后，才能称为“完成席位结果优先”已交付。
- **C：后续增强。** 历史执行选择器与版本列表、复杂分组和搜索、单席结构化 verdict / finding、意见关系和证据关联。首期不画出尚不存在的可信结论与计数。

不改 `kind=squad` 的只读观察契约；不把审查结论解析用于 ideate。沿用 Driver Selection / Council / Reporter / Run / Autonomous Run / Attempt / Aggregator / Task Template 术语。Host 不可用时提供连接状态与恢复说明，不自动启动 Host。

## 2. 信息结构

### 2.1 报告页

主阅读区按以下顺序组织：

1. **上下文。** PR 标题和链接、审查提交 SHA、Run 状态。缺少 SHA 时显示“提交信息缺失”，不把最新 PR 提交代入历史报告。
2. **本轮审查。** 汇总报告及已有可靠发现账本；Aggregator 未完成时显示等待或运行状态，已完成席位无需等它才能阅读。
3. **当前修复。** 仅存在 `pipeline` 时显示独立面板，包含真实阶段、轮次、更新时间和后续复审关联。审查席位计数不充当修复进度。
4. **报告正文。** 完整 Markdown；结构化摘要不可用时仍是主要内容。已有账本可提供 Run 级发现视图，但不据此生成单席意见。

桌面右栏只有一份“审查席位”紧凑列表，**删除旧稿重复的“席位结果”Tab**。列表展示职责、执行状态、时长、真实当前活动或结果可用性。Aggregator 单独标为“汇总报告”，置于独立审查席位之后。

侧栏列表、详情中的席位切换、窄屏列表必须共用同一数据选择器、稳定身份和排序：按本轮声明的席位顺序排列，Aggregator 最后；不因完成时间、发现数或当前选中项自动重排。模型与 Driver 是次级信息，只有职责重复时才参与区分。

“轮次”仅来自真实 `pipeline.round` 或服务端明确关系；`againstRunId` 只证明关联，不能自行计算“第 N 轮”。

### 2.2 席位详情

- 提供宽阅读区，头部固定职责、执行状态、必要的模型信息、执行来源和关闭入口。
- 首次打开已结束席位：**执行及结果状态 → 完整报告 → 可展开的过程**。首期不为缺少结构化摘要保留大片空洞。
- 首次打开运行中席位：**当前活动 → 最新过程**。不展示假百分比或推测剩余时间。
- 执行成功且普通自然语言报告可读：用中性色说明“执行完成”“完整报告”“暂无结构化摘要”。可在次级说明中写“结果未解析”；这不是整页黄色警报，也不是等待后台继续解析。
- 执行失败：首先显示“执行失败”和已记录原因，再提供保留过程。失败不是“需要修改”，过程里的结论文本不能生成通过/不通过徽标。没有原因时显示“未记录详细原因”。
- B 尚未接通时，A 的入口保持“查看进展/查看详情”；不得把 live 启发式截取内容包装为“完整席位报告”。

### 2.3 操作

“重新读取”只发起读请求，不执行 Agent。当前 Host actions 只有 `fix`、`re-review`，不能以 `re-review` 冒充单席重试；首期不提供没有可靠执行接口的“重试本席”。执行动作沿用现有范围与权限。

关闭后焦点回到触发入口；Escape、席位切换、展开按钮均可键盘操作。模态布局管理焦点，常驻侧栏不设伪模态。状态同时使用文字和形状，不仅用颜色。普通席位计数使用主文字色，红色用于明确的问题严重性或执行错误。

## 3. 状态三轴

界面分别建模 **执行状态、结果可用性、过程可用性**。结构化解析是结果的附加属性，不替代这三轴。

| 执行事实 | 结果事实 | 首屏表达与内容 |
| --- | --- | --- |
| pending / queued | 尚未生成 | 等待启动 / 排队中；无真实时间戳不显示排队时长或名次 |
| running | 尚未生成 | 当前动作或“等待首条记录”；真实执行时长 |
| running，暂无新事件 | 尚未生成 | “最近活动 N 分钟前”“暂时没有新记录”；不判定卡死，不持续动画假装有输出 |
| success | 尚在读取或可证明短暂落盘未就绪 | “执行完成 · 正在读取报告”；有限重读，不能永久处理中 |
| success | 正文可用，无可靠结构化结果 | **正常报告阅读态**：“执行完成”“暂无结构化摘要”；不显示 0 项发现、通过或需要修改 |
| success | 持久化正文为空 | “执行完成 · 暂无结果正文”；过程仍可查看；空输出不等于没有问题 |
| success | 读取失败 | 局部“报告暂时无法读取”与重新读取按钮；不清空过程、不拿 live 替代正文 |
| success | C 提供可靠逐条 finding，但无 verdict | N 项发现 / 未列出发现；不得自动判为通过 |
| success | C 提供明确 verdict | “独立意见：通过/需要修改”；Aggregator 用“汇总结论”；相邻保留不完整提示 |
| failure / cancelled | 没有有效当前结论 | 执行失败 / 已取消；已保存过程可读；不展示旧成功结果为当前结果 |
| 未知状态 | 任意 | 状态未知；已有可验证正文和过程仍可读，不推断完成 |

现有 `CliRunAttemptResult.parseStatus=parsed` 只表示摘要器识别到标题或严重性文本。当前计数由正则产生，**不是可靠逐条 finding 的数量，更不是 verdict**。首期单席不把这些计数做成醒目的结论指标；可读原文优先。Run 级真实账本计数不受此限制，但必须标明其范围。

| 过程事实 | 展示与处理 |
| --- | --- |
| 首次加载 | 小型读取提示；不清空已存在的结果 |
| 运行中无记录 | 等待首条记录 |
| 已结束且响应为空 | “暂无可读取的过程记录”；当前 API 不能证明是没保存还是文件读取失败 |
| 已返回明确截断事件 | “过程记录已截断，当前展示已保存内容”；不利用尾部片段推导结论 |
| HTTP/网络失败，有缓存 | “过程读取失败，已保留读取内容”；继续阅读并可重读 |
| HTTP/网络失败，无缓存 | “过程暂时无法读取”；不能显示成没有记录 |
| 过程与当前执行无法一一对应 | 标为“该席位已保存过程”；提示版本未单独记录，不称为“本次执行完整过程” |

页面级规则：部分席位结束显示 X / Y 席已结束；全席终态且 Aggregator 运行显示“正在汇总”。缺席或失败时，即使汇总报告存在也相邻标明结果不完整。修复声明成功而未验证用“声明已修复 · 待验证”。旧 SHA 的报告不能证明新提交通过。

## 4. 进行中与阅读连续性

1. 首次打开运行中席位默认跟随底部；滚离底部即暂停。出现“新增 N 条活动 · 回到最新”，只有明确回到底部或点击该入口才恢复。
2. N 按稳定活动行计数，不按 delta、字符数计数；向同一文本活动追加字符不增加 N。首期允许使用确定性折叠，不要求复杂工具分组。
3. 暂停跟随只暂停滚动，不意味着永久无限追加缓存。数据缓存、DOM 与轮询遵守交付计划的容量规则；回收不得丢失已保存数据的可达性。
4. 完成事件只更新状态、提供“报告已就绪 · 查看报告”，不切换视图、不替换内容、不收起过程、不抢滚动或焦点。插入报告不能推移正在阅读的历史锚点。
5. B 上线后，视图状态按 `runId + attemptId + executionRef` 保存：当前模式、展开项、稳定活动锚点与偏移。先恢复锚点，再恢复偏移；新执行不复用旧执行结果或阅读位置。
6. A 阶段没有可靠 `executionRef`，只保证当前挂载会话内的阅读连续性；检测到运行重置或无法确认代次时清除相关数据缓存并重新读取，不声称跨 resume 恢复正确。
7. 切席使用请求代次/取消保护，迟到响应不能覆盖当前席位。重连按游标续读并去重；服务端事件序号重置必须重建对应缓存，不能继续沿用旧游标而永久漏数据。
8. “最近活动”来自真实活动事件或明确 heartbeat。进度文件 `updatedAt` 不能叫“Agent 最近输出”；时间不可解析时显示“时间未知”。
9. 记录一个工具调用结束，不等于工具成功或测试通过。当前事件没有可靠 `toolCallId` / exit code，同名并发工具不得展示无法证明的配对与精确耗时。

## 5. B：当前执行结果最小接口

后端工作项独立排期，先完成语义验证再接前端。接口名称可调整，以下语义不可省略：

```text
GET /api/v1/cli-runs/:runId/attempts/:attemptId/result
```

```ts
type CurrentAttemptResult = {
  runId: string;
  attemptId: string;
  executionRef: string; // 当前实际执行的稳定不透明身份
  executionStatus: "pending" | "queued" | "running" | "success" | "failure" | "cancelled";
  availability: "pending" | "available" | "empty" | "unavailable";
  markdown: string | null;
  truncated: boolean;
  failure: { code: string; message: string } | null;
  reusedFrom: { runId: string; executionRef: string } | null;
};
```

**本期没有 `versions[]`，不提供历史选择器。** 当前版本识别正确性是 B 的必要条件；完整历史浏览属于 C。前端将其作为原子快照消费，不能把一个响应的状态与另一次执行的正文拼接。

- `attemptId`、模型名、`attemptNumber` 均不能单独成为执行身份。重试与 `review.resumed` 会复用 Attempt，必须区分实际执行。服务端先解释 durable 顺序与显式复用关系；浏览器不自行推演代次。
- `executionRef` 在同一次执行从运行到终态时保持稳定，append、resume、原子重写后仍指向同一执行。B 的语义验证需证明现有记录能否做到；若不能，补最小持久化身份事件，不用随机前端 UUID 或文件 mtime 掩盖缺口。不要求建立新数据库或重写全部历史。
- 当前重新执行时，旧成功正文不能作为 fallback。只有显式 `reusedAttemptIds` 证明复用才返回 `reusedFrom` 并显示“复用已有结果”；Aggregator 每次 resume 重新执行。
- 正文只来自匹配执行的 `attempt.finished.output` / `aggregation.finished.output`。不得从 live 正则提取、按文本长度挑选，或返回最后一次成功冒充当前失败。
- 尚未结束为 `pending`；终态而短暂落盘未就绪可有限重试。确定的空输出为 `empty`，无法确定正确正文为 `unavailable`。前端在有限重试后提供重新读取，不把所有异常永久当 pending。
- 目标记录超过已有目录摘要扫描上限时必须仍可读取全文，或明确 `truncated/unavailable`。B“完整报告”验收要求正常目标全文可读；截断只是诚实退化，不能以截断状态冒充全文能力已完成。
- 保留 session 认证、Run/Attempt 校验、目录边界、非符号链接规则和 Markdown 安全渲染。损坏记录/错误信息不得回显敏感原始行。
- 旧 live 文件仅按 `attemptId` 存放，B 不顺带宣称已有历史过程版本映射。无法证实与当前执行一致时，按 §3 标注席位已保存过程。

| 能力 | 当前事实（`3f968a2`） | v2 处理 |
| --- | --- | --- |
| Run 状态、席位、时长、修复阶段、总报告 | detail 的 `progress/pipeline/markdown/truncated` 已有 | A 直接使用 |
| 席位摘要 | `shared/runtime/seat-result.ts`，240 字摘要与启发式计数 | 不升格为结构化结论 |
| 单席最终正文 | durable transcript 已落盘；浏览器无专门读取接口 | B 独立工作项 |
| 现有结果面板 | `AttemptLiveTranscript` 使用 `splitSeatDeliverable()` 从 live 挑正文 | B 替换来源；A 不宣称其为权威全文 |
| 过程接口 | 返回 `events/nextSeq/done`；按游标过滤前会同步全读全解析 sidecar | 容量验收必须测 Host 成本，游标不是磁盘增量读取保证 |
| 前端轮询与折叠 | 2 秒轮询；追加复制数组；重新折叠事件；完成后停止 | A 验证跟随与缓存，按基线决定增量折叠/窗口化优化 |

## 7. C：增强能力的启用条件

- **历史执行浏览：** 独立 `versions` 列表与明确历史标识；选择历史后不混入当前结果。只有可靠映射才附历史过程。
- **分组与搜索：** 按真实类型和时间顺序确定性分组；跨进展文本、执行边界或截断节点断组；不得调用模型编写“正在验证假设”等阶段。搜索按字面量、选定席位/执行范围进行，截断或未加载完整时明确范围。命中不抢阅读位置。
- **结构化意见：** verdict、逐条 finding、解析版本与出处都有明确数据契约后才显示；零发现不自动升级为通过，多数意见不是正确性证明。
- **证据关联：** 指针绑定 Run、SHA、Attempt、执行身份；修复声明不等于独立验证，缺席不等于反对。

首期画面不保留上述尚不可用功能的假数值、假关系或无效按钮。
