## 本轮改了什么

1. 大红结论退到小状态标签，报告内容成为主要视觉信息；减少重复导航、巨大状态图标与卡片边框。
2. 增加正常原文阅读态与失败保留过程态。首期不把启发式单席计数或 verdict 放进画面。
3. 运行中画面直接展示暂停跟随；修复页直接展示“只有真实阶段、暂没有过程记录”的状态。
4. 图中的重复席位 Tab、红黄单席数字、虚构独立验证、锁定共识、修复耗时等已移除或改正。
5. 把接口与视觉交付拆成 A/B/C；补充 2 MiB、高事件密度、长文本、真实两小时 soak 的验收方案。

## 6 张图及交付归属

| 图 | 交付 | 说明 |
| --- | --- | --- |
| 01 审查总览 | A 布局；B 支持单席全文入口 | Run 级汇总可用；右栏一份席位列表 |
| 02 原文可读、未结构化 | B | 正常报告阅读，不是失败页 |
| 03 运行中、暂停跟随 | A；B 支持完成席位全文入口 | 当前动作与旧记录同时可见 |
| 04 席位失败 | B | 无审查结论，已保存过程可读 |
| 05 历史过程检索 | **C，后续增强** | 分组、搜索、命中导航不阻塞 A/B |
| 06 修复进行中 | A | 旧结果与当前阶段分区，无虚构细节 |

A 可先发布，与 B 的后端工作并行。图 01/03 展示 A+B 联动；A 单独发布时“阅读”入口使用“查看详情”，不得宣称已有可靠完整席位报告。B 必须通过真实 durable 读取与身份映射验收。历史版本选择器不属于 B。

## 交付文件

`screens/` 保存 6 张内置 Image Gen 生成的 PNG 原图，`design-tokens.json` 保存 CSS 数值，`board-data.json` 保存逐图注释，`generation-prompts.json` 保存生成与精修提示，`manifest.json` 记录尺寸与哈希。没有 Figma 文件或产品交互实现；HTML 只是设计画板，图片内产品按钮不可操作。

设计基准为 1440 × 1024 CSS px；PNG 的实际尺寸见 manifest。图片用于视觉比例与层级参考，文本与状态规则已经在相邻注释中说明。所有 PR、代码、时间与计数均为演示数据。

实现顺序：先看画板与每图注释，再读任务书和交付计划，按 A/B/C 的各自验收完成。数值和状态含义以规格为准；不能把缺少接口的数据补成假状态。
