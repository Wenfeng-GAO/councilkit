## 交付顺序

1. **A 独立界面改善**：审查/修复分区、单份稳定席位列表、当前动作、暂停跟随/回到最新、完成不打断阅读。复用当前已有能力。A 单独交付时入口仍为查看详情，不宣称已读取可靠完整席位报告。
2. **B 可靠结果**：后端独立工作项 B0 验证当前 executionRef 语义，B1 接 current durable result API；前端 B2 可按冻结契约同步开发；B3 真实联调才算完成。必须保证当前执行身份与正文一致；完整历史版本浏览与 versions[] 不属于本期。
3. **C 后续增强**：历史版本选择、图 05 的复杂分组检索、结构化单席 verdict/finding、证据关联。C 不阻塞 A/B，不把它的界面塞进首期假装已有能力。

## 必须落地的真实状态

- 普通自然语言正文可读但没有结构化摘要：正常文档阅读态，不显示假结论、0 项问题或整页黄色告警。
- 席位失败：准确失败原因、可读过程、没有本次审查结论；不回退旧成功，不把 live 末尾 approve 当成通过。
- 过程缺失或截断：不影响 durable 原文读取；过程版本无法证明时如实标明。
- 用户正在回看历史时出现新事件/完成：保留滚动、展开与焦点，显式点击后才跟随或看报告。
- 修复运行：旧结论绑定原 SHA；当前阶段来自 pipeline，不编造运行时长、Run ID、活动时间线或共识。
