# CouncilKit v2 · 视觉规格

本规格对应 6 张 v2 图。交付范围直接显示在 [画板](DESIGN-BOARD.html) 每图旁边；运行规则见 INTERACTION-SPEC，工程分期与性能验收见 DELIVERY-PLAN。父目录 v1 不再作为实现目标。

## 1. 设计原则

- **报告内容优先。** 标题讲清楚对象，状态作为辅助标签；避免用巨大“需要修改”占据首屏。
- **导航各司其职。** 总览右栏进入席位；席位标题旁的选择器切席；文内目录定位原文；C 的筛选只影响过程。删除重复席位 Tab。
- **颜色少而有含义。** 数字中性色，绿色表示执行完成，红色表示明确失败或严重性，蓝色表示进行中，黄铜表示选中与主要操作。
- **每个状态都可使用。** 报告未结构化采用正常文档阅读；失败交代原因与已保留内容；缺过程记录仍能看真实阶段。
- **当前范围直接呈现。** 不用尚未存在的单席 verdict、发现计数、验证标记装饰首期页面。

## 2. 布局、字阶与颜色

精确数值见 [design-tokens.json](design-tokens.json)。桌面基准 1440 × 1024，左导航 208，主边距 40，列间距 32。总览右栏 260；实时席位列表 248；原文列最大约 800。让主要中文段落保持约 32–44 字/行，长路径可换行，代码可局部横滚。

正文 15/25，次级信息与代码 13/20，页面标题 28/36，章节标题 20/28。原文自身标题进入正文层级，不与页面标题争夺大小。核心信息不用小于 13px 的字号。

背景 `#0b0d10`、表面 `#15181d`、次表面 `#1e2128`、线 `#232830`、正文 `#e6e8ec`、次文字 `#a0a6b0`、暖标题 `#efe4cf`、黄铜 `#c4a574`。绿 `#22c55e`、红 `#f85149`、蓝 `#58a6ff`、警告 `#d29922`。普通计数不染红或黄。纯色背景和按钮，不复刻生成图中的光泽或微纹理；词标复用现有资产。

按钮/输入高 40、圆角 6；间距采用 4/8/12/16/20/24/32/40/48/64。状态文字配小图形，不靠颜色独立传义。页内主操作通常只有一个；没有动作必要时允许没有主按钮，例如 06。

## 3. 页面结构与数据门槛

| 图 | 固定层级 | 数据门槛与操作 |
| --- | --- | --- |
| 01 总览 | PR → 本轮摘要 → 优先问题 + 席位右栏 → 汇总正文 | 汇总结论/发现来自真实 Run 证据；“开始修复”说明会修改并推送，沿用现有流程 |
| 02 未结构化原文 | 席位身份 → 执行状态 → 中性来源说明 → 原文 → 过程 | B 的 durable 正文；目录取真实标题；无解析等待动画、无 0 问题 |
| 03 暂停跟随 | Run → 稳定席位列表 + 当前活动 → 历史 → 回到最新 | 当前动作来自真实记录；暂停不等于暂停 Agent；A 单独上线完成席入口为查看详情 |
| 04 执行失败 | 身份 → 原因 → 看过程/复制诊断 → 已保存内容 | 不产生通过/需修改结论、不提供无 API 的重试；失败原因缺失则明确缺失 |
| 05 搜索 | 身份 → 原文入口 → 查询/范围 → 命中 → 前后导航 | C 才启用；只搜已保存内容、按字面匹配，不伪造工具输出 |
| 06 修复 | 原审查摘要 → 真实当前阶段 → 可读资料 | 不用 X/Y 审查数表示修复进度；没有时长与过程数据就不画出来 |

当前执行身份必须随结果绑定，但不要求向普通用户展示内部 opaque token。02 中 e3 是示例显示标识；生产可用“本次执行”，完整 ref 进入来源详情/复制诊断。B 没有历史选择器。只有真实显式复用时显示“复用已有结果”。

席位列表与菜单共用声明顺序；不因状态/数量自动换位。所有单席例子是独立报告，Run 级账本数量不作为单席数量。示例“兼容性审查”不能成为前端强制重命名规则。

修复阶段严格映射：起草方案、方案陪审、汇总方案、落地、复审、完成。06 的箭头仅表达 pipeline 阶段；03 的并行席位没有连接箭头。

04 的“最后记录活动”仅在来源可证明与当前执行一致时展示；如果旧 sidecar 只按 attemptId 存储，转为“该席位已保存过程”，相邻标明版本未单独记录。这是数据状态切换，不是默认声称保存了当前执行全过程。

## 4. 微交互与补充状态

- 正文读取中只在正文区显示小骨架；过程仍可读。结果为空、读取失败、未结构化三种状态不合并。
- 无结构化摘要采用中性说明“报告已生成，暂无结构化摘要。以下为席位原文。”不使用 warning 图标或黄色容器。
- 失败主要操作是查看过程，次操作复制已净化诊断；对旧成功不做 fallback。
- 新事件只更新正在跟随的过程。回看历史时“已暂停跟随 · 新增 N 条活动”；完成时增添“报告已就绪”入口，用户点后才转到结果。
- 01 的问题行展开后保留同一列表位置；完整报告可折叠，但无法解析时原文应成为主区。
- 05 搜索无结果显示“没有匹配的记录 / 清空搜索”；没有过程记录使用另一空态。匹配数不得含未加载内容。
- 06 若出现真实失败或需用户操作，替换当前阶段区为准确原因；不能持续 loading 假装执行。

## 5. 响应式与可访问性

≥1280 保留图示分栏；1024–1279 边距 24、原文目录收为目录按钮；768–1023 使用可折叠全局导航、内容单列；<768 边距 16、标题 24/32、席位选择器代替长横排，主操作不挤出屏幕。总览右栏在窄屏成为正文后的一份列表，不复制 DOM 造成两套焦点顺序。

键盘焦点 2px，沿用现有紫色 focus token；可点击目标至少 40px。关闭后回焦点源。折叠、筛选、下拉具备对应的可访问名称与状态；模态才管理焦点圈定。`aria-live=polite` 只播报状态/活动条数，不能逐字符播报过程。

过渡约 150ms，尊重 reduced motion；跟随用即时定位而非每 delta 动画。正文 4.5:1、非文字控件 3:1 是待实际验证的目标，生成图不构成合规保证。

## 6. 实现核对

使用本目录图和旁注进行视觉比较，不使用父目录旧稿。分别保存 1440、1024、390 宽度实现截图，至少覆盖未结构化可读、失败、暂停跟随、修复只有阶段、读取异常。静态设计图不能充当真实界面验收截图。

核对层级、列表密度、换行、焦点、遮挡和状态含义；对数值与数据契约准确实现，不逐像素复刻生成文字。长会话与容量测试独立执行，不以“看起来流畅”替代测量。
