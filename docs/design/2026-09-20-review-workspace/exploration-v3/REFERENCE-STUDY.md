以上最后一列是本次判断，不是参考产品对 CouncilKit 的建议。

## v2 最值得改变的视觉问题

1. 01 的有效发现内容出现在约 y400，标题与摘要过高。探索将上下文栏控制到约 48px，报告标题 24px，正文保持 16/26；不是把所有文字一起缩小。
2. 全局导航占约 208–232px，入口少且视觉偏亮。目标为 176–184px 的低权重导航，工具行紧凑，阅读区拿回空间。
3. 席位在总览右侧、运行页左侧、结果页下拉，位置随状态改变。新方向优先比较稳定席位侧栏与稳定顶栏。
4. 完成绿字、金色按钮、蓝色链接与红色标签同时显眼。执行成功采用小标识与中性文字，复制/打开 PR 降为次级动作。
5. 过程每行占高过大，且页面角色像排版文档。过程观察可以做局部面板，与报告共存而不混淆所属席位。

## 三种同内容布局探索

三张使用同一 Run：piston #413、3/5 席结束，阅读已完成的对抗审查原文；无结构化 verdict 或发现数。编号严格对应本轮图片在对话中展示的顺序。

1. [固定席位工作台](options/01-workbench.png)：固定上下文栏、常驻席位列表、右侧报告/过程区域。重点验证反复切席时是否更稳定。
2. [专注报告阅读器](options/02-reader.png)：上方固定席位导航、居中原文、轻量目录。重点验证长报告的阅读舒适度。
3. [报告与过程双层工作区](options/03-console.png)：上方读已完成报告，下方观察另一席过程；两个席位范围分别明确。重点验证同时阅读与跟进运行是否值得额外复杂度。

先选择布局骨架，再把同一骨架应用到总览、未结构化报告、失败与运行中；本轮没有再次将三个方向各自扩成全套页面。

## 探索边界与下一步精修

- 三张是布局探索，不是新的功能承诺或前端任务书；v2 的可靠结果、版本身份和 A/B/C 分期仍适用。
- 02 生成图出现“项目”“智能体”导航，属于生成偏差，不批准新增页面；正式方案需恢复首页、新建讨论、产品创意、报告与设置。
- 02 的“完整执行过程”字样不能进入正式设计，最终必须标明“已保存过程”。原记录可能截断或缺少版本映射。
- 03 同时展示对抗审查报告和可维护性审查过程，需保持两个独立且可见的席位范围，不能复用一个含糊 selectedAttempt 状态。
- 图上字号、状态点、边界仍需选定方向后精修；特别不能将像素图尺寸直接作为 CSS 尺寸。

本轮使用内置 Image Gen。原始提示词保存在 generation-prompts.json。没有修改产品源码或已批准的工程范围。
