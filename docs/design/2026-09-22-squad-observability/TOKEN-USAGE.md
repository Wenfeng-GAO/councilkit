## 开销分析

1. 含缓存按已记录总量计算，Codex占72.2%；只看非缓存输入+输出，Codex399,528，cfuse至少560,866，Codex约41.6%。cfuse尚有缺口，因此两者占比不是完整真实份额或费用份额。
2. Codex非缓存输入的323,981发生在最初产品设计/交接阶段（约占Codex全部非缓存输入86.7%）。虽然文件按独立需求组织，仍沿用了长历史对话，未做到短上下文隔离；这些输入不能理解成输出了32万token的PRD。
3. 委派cfuse后，Codex新增的非缓存输入+输出是69,307；相对cfuse已知同口径用量占约11.0%。但本阶段缓存读取14,572,672很高。本任务42次工具调用中24次包含等待，长上下文被反复读取，平均每条usage记录约36万输入。
4. 原型承担7个场景、多角色、筛选、抽屉、轮次、模拟停止与77项检查，HTML约87KB、测试脚本约19KB；对“先确认形态和样式”的第一版偏重。语法、焦点、计数、抽屉定位等修正带来往返，三次定时终止又切断最终用量回执。
