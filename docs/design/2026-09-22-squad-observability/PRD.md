# Squad 自动修复过程工作台 · PRD v0.1

状态：待用户确认产品形态与样式。独立新需求，不属于已交付运行时切换，不修改当前运行任务。负责人：Codex（产品与交互设计）；HTML制作：cfuse。2026-09-22。

## 1. 问题与目标

真实问题：修复页长期只显示“进行中”，用户无法确认 Agent 是否在工作、哪个角色正在执行、刚改了什么、是否卡住、下一步该做什么。一次现场检查发现后台持续写日志、Builder正在修改恢复代码，但父Run的attempts为空，页面没有过程入口。这是观察路径缺失，不能用持续转圈或假进度填补。

用户在8秒内应能回答：①当前在做什么；②最近是否还有活动；③目前需要谁做什么。进一步可定位某次工具操作的输入、结果、文件变更与对应证据。过程热闹不等于修复有效；执行结束不等于已准出。

成功标准（后续真实实现验收）：可用事件落盘后2秒内出现在页面（本地正常连接目标）；刷新后能恢复已持久化过程；三类关键问题可在一屏内回答；没有输出时明确说明观察情况；控制器没有准出证据时页面不显示已准出。指标是设计验收目标，不是现有能力声明。

## 2. 范围

P0：运行概况、动态角色列表、统一活动时间线、角色/类型/关键词筛选、详情抽屉、跟随控制、连接与静默状态、异常原因和已有恢复入口、验收证据与候选身份、历史轮次只读查看。

P1：更丰富的变更浏览、跨轮对照、结构化成本统计。当前原型包含轻量文件diff预览与轮次选择以确认方向，不承诺完整代码评审器。

不在本需求：更换控制协议、自动扩预算、模型自动fallback、运行中跨模型续接、PR发布操作、新的通用Agent终端。复用现有停止/恢复能力；当前设计不新增一键绕过失败的操作。模型额度不足只提供原因与换席步骤，不能伪装热切换。

本阶段交付仅PRD、交互规范、fake数据原型和截图。所有按钮只改变原型内存状态，不调用Host、不影响真实PR或Run。

## 3. 页面结构

保持 CouncilKit 已选固定席位工作台语言：184px全局导航、232–248px执行角色栏、弹性主内容；详情用可关闭抽屉按需打开。窄屏改为角色选择器和全宽抽屉，不引入第二套设计语言。

- 页面上下文：报告路径、示例PR与修复轮次，原目标一句话、当前阶段、耗时。长runId与模型参数折叠到运行详情。
- 阶段路线：准备 → 编码修复 → 独立评审/验证 → 终验 → 准出。评审与验证可并行，视觉上不能强制串行。阶段路线不换算百分比。
- 左侧执行角色：全部活动、编排与开发、独立评审、独立验证。主Planner/Builder共享执行时归一条；内部子阶段在详情体现。可选Planner B按真实执行计划显示，不制造空席。区分待启动、活动中、已结束、失败。
- 主视图默认“活动”，另有“验收与改动”。活动以时间顺序展示关键里程碑、Agent公开进展摘要、工具开始/完成、文件读写、命令结果。高频碎片合并成一条可展开操作，不逐token刷屏。
- 常驻观察状态：进程/Host信息与日志连接状态分开；最近有效活动时间、最后收到数据时间。主视图不会因为选中已完成角色而自动跳到活跃角色。
- 详情抽屉：操作类型、角色、起止/耗时、文件或命令、实际结果、来源轮次与执行身份；命令长输出折叠，文件变更只显示已记录diff，不能把仅读取显示为修改。

## 4. 关键交互

I1 进入运行页：选中“全部活动”，展示最近活动并跟随底部；进入某角色时保留筛选与该角色滚动位置。刷新不清空已持久化事件。
I2 跟随：点击“暂停跟随”只停止自动滚动，数据继续接收；出现“有N条新活动 · 查看”按钮。恢复跟随后定位最新。用户手动向上滚动也暂停跟随；不自动滚回底部抢阅读位置。
I3 筛选：角色、事件类型（全部/工具/进展/状态）、关键词组合生效；无匹配时提示当前筛选并提供清除，不显示任务没活动。
I4 详情：点击命令/文件活动展开抽屉；Esc/关闭可收起，焦点返回触发按钮；长路径可换行，复制成功后才提示。失败操作的错误片段默认可见。
I5 连接中断：保留缓存和选中项，顶栏标“连接已断开 · 当前是最后一次已知状态”，显示最后同步时间；无法确认运行状态，不把它判失败，也不继续走动假时钟制造活跃错觉。原型“重新连接”回到对应演示快照。
I6 静默：默认演示超过3分钟无新有效活动、最近心跳仍在，只提示“暂时没有新活动，进程仍在线”；不能断言卡死，不能自动重试。阈值是待校准产品参数。无心跳来源时显示“进程状态未知”，不要补出在线。
I7 需要处理：把原因和受影响角色放在时间线之上，保留之前过程。额度不足显示“独立评审额度不足”，提供“查看换席步骤”，解释停止旧执行、明确选模型、新会话、v2同链预算继承；不提供会清零预算的“重新开始”捷径。剩余预算不代表剩余账户额度。
I8 停止：常驻低强调“停止任务”，点击确认弹窗说明停止当前执行、保留记录和已用预算。与“暂停跟随”明显分离。原型确认后进入“已停止（模拟）”，不伪装为修复完成。
I9 轮次：默认当前轮，可看第1轮记录；历史轮显示只读条幅及“返回当前轮”，无停止/恢复动作，不能把旧轮通过/活动混入当前轮状态。
I10 验收：每项不变量显示待验证/通过/未通过/证据不足及证据入口。“已执行完”和“已准出”独立。已准出须展示候选SHA、基准SHA、准出时间及必要证据已核验；无来源不显示成功。

## 5. 状态模型与文案

| 场景 | 主要文案 | 可观察事实 | 允许动作 |
|---|---|---|---|
| 编码中 | 正在修复会话恢复路径 | Builder活动、文件操作、最新更新时间 | 看详情、筛选、暂停跟随、停止 |
| 独立评审/验证中 | 候选已提交，正在独立核验 | Reviewer与Verifier并行；Builder停写 | 查看两角色进展、停止 |
| 长时间静默 | 暂时没有新活动，进程仍在线 | 上次活动3分48秒前；最近心跳8秒前 | 查看最近记录、运行详情、停止 |
| 连接断开 | 连接已断开，显示最后已知状态 | 上次同步时间；任务当前状态未知 | 重新连接、读缓存；控制动作不可用 |
| 额度不足 | 独立评审额度不足，需要处理 | 明确失败角色和已记录错误 | 看原因、看换席步骤；不自动fallback |
| 候选已完成 | 本地候选完成，等待最终准出 | 执行已结束，远端身份尚未核验 | 查看证据，不显示已交付 |
| 已准出 | 已准出 · 证据与提交一致 | 同一SHA必需证据齐全 | 查看/导出证据，无停止按钮 |
| 用户停止 | 已停止 | 用户停止时间、历史/预算保留 | 查看记录；不自动重新运行 |

首屏不展示“4/6席=67%”等伪进度。验收2/5是证据覆盖数，不是任务完成率。Token没有完整回执就显示“暂无完整用量”，模型500K上下文不是消耗量。

## 6. 数据与可观察性契约（产品层）

每条事件具有稳定身份、轮次、执行身份、角色、发生时间、接收时间、事件类型、状态和可读摘要。相同事件重连重放不重复；乱序到达不把新状态回退；历史执行结果不能覆盖当前重试。工具started/finished合为一个操作，超时未收尾显示“未收到结束记录”，不补成功。

日志连接、进程存活、任务阶段、业务准出、验收证据分别表示。原始日志不是业务状态权威，阶段以控制器为准。无进程证据不凭近期日志声称进程在线。暂时没有流式日志但有最终报告时，明确说明证据可用范围。

可读层使用公开进展与工具事实，不默认呈现模型隐藏推理。命令参数、日志和文件内容在服务端脱敏；输出截断必须有标记，可分页查看已有历史。前端只加载有界窗口（建议最近200条），不能把数十MB日志反复全量灌入页面。

## 7. 验收清单

A1 每个演示场景首屏可识别当前阶段、最近活动、是否需介入。
A2 暂停跟随期间模拟新事件只增加未读数，不移动阅读位置；恢复后归零。
A3 角色与事件筛选可组合、可清除；详情内容属于选中事件。
A4 静默/断线/失败三种状态不同，断线不清记录、不宣布任务终止。
A5 同一轮多个角色并行可见；历史轮只读，无操作入口串到当前轮。
A6 候选结束不显示已准出；仅已准出场景显示完整身份与证据。
A7 停止有明确确认和“模拟”标识；取消不改状态。
A8 模型额度故障的步骤不暗示原地换模型或清空预算。
A9 1440/1280桌面和390窄屏布局可用、无页面横向溢出；键盘焦点、Esc、reduced motion可用。
A10 页面所有外部请求为零，不访问43127/API/真实文件；fake badge常驻，场景控制与产品控件分开。
