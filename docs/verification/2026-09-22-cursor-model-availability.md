# Cursor 审查模型失效修复

## 原因与边界

2026-09-22 的 Cursor 实时目录不再接受 `grok-4.7[context=500k,reasoning_effort=xhigh,fast=false]`。当前合法别名 `grok-4.7-xhigh` 的新会话回执为 `Grok 4.7 256K Extra High`，恢复回执也可能省略容量。不能把它当作原500K模型来验证或跨模型恢复。

失败审查的席位配置来自 `/api/v1/review-jury`（CLI jury show/save），不是直接使用 agents.json 的默认绑定。界面此前把已保存的旧ID重新拼回实时目录，同时只按配置结构判断是否可启动；因此失效Aggregator仍被提交，健康探针拒绝后连带取消其余未启动席位。

## 改动

- 默认审查席位读取当前Cursor目录后再放行启动；失效绑定明确提示，保存时也要求显式选择有效ID。旧设置保留，不自动更换模型/容量，不改历史manifest或Run。
- 当前Grok别名接受已观测的256K显示名及省略容量的显示名；旧500K请求、其他effort/fast/family不会被误认。
- Cursor健康探针只有TIMEOUT允许再试一次，最多两次，每次仍有原来的60秒上限。无效模型、其他驱动及取消操作不走该重试，记录总探针耗时。
- repair默认值和已有冻结500K身份没有自动迁移。是否将现有审查席位改为256K需用户选择。

## 验证

- 相关unit/Host/CLI测试：22通过，1个需显式启用的live SDK测试跳过。
- CLI review全文件：75通过，包含超时后恢复、两次超时封顶、无效模型不重试。
- 独立端口浏览器用例：1通过。验证失效模型阻止启动和保存、零自动配置写入、用户显式重选后恢复可用；没有实际发起业务审查。
- 四套TypeScript检查、改动文件Biome检查、前端/Host/CLI构建通过。
- 真实Cursor只读探针：canonical ID成功（26.469秒），auto首次65秒超时、第二次44.15秒成功。旧500K参数及effort替代写法均被拒绝。未修改CLI版本、凭据或账户模型。
