# 审查结论与问题清单的可读性修复

验证样本：`ck-review-142035e3-c895-4523-9781-f9258db908f9`。

## 根因

- 执行状态、Aggregator 的 COMMENT 意见、账本阻塞是不同维度，页面未解释其关系。账本按重大/致命且未验证关闭或接受不修计算阻塞，不读取报告中的“不升阻塞”声明。
- 报告以 `**历史ID**` 重述问题时，旧提取器只识别反引号包裹的 ID，因而给同一问题新增 hash ID。
- 展示标题截取机器 ID、席位状态和长文件名，实际反例位于截断范围外。

## 修改

- 概览同时显示中文报告意见与账本门禁；COMMENT/APPROVE 遇到未解除的账本阻塞时，突出“审查结论待核对”。缺失或不完整的账本证据不会显示无阻塞。
- CLI 识别前导粗体历史 ID；历史报告阅读投影按明确的完整 ID 引用合并，保留每条原始记录和验证信息。
- 问题行增加筛选间稳定的序号；从原文反例提取标题，文件位置独立展示。

## 验证

- 相关 Vitest：120 项通过，包含报告解析、CLI 账本、投影和静态渲染回归。
- Playwright：11 项通过，覆盖 1440/900/390px、展开证据、筛选序号和重复记录。
- `pnpm typecheck`、`pnpm build`、改动文件 Biome 检查及 `git diff --check` 通过。CSS 保留原有无关格式；该文件单独检查 lint。
- 真实 Host 浏览器回放：20 条账本记录呈现为 18 个阅读问题；3 条阻塞记录呈现为 2 个阅读问题；页面无异常，原始 findings.json 哈希未变。

## 边界

本次修正身份提取及展示，不将自然语言“不阻塞”转换为接受风险或关闭证据。归档过滤和名称/ID 寻址的反例继续独立保留。若要让报告的“本轮不阻塞”正式影响修复门禁，需要另行定义结构化、可追溯的适用范围裁决。
