# 问题短标题与解释生成修复

日期：2026-09-28。GSD quick：`260928-quv`。

## 根因与修复

- 旧输出契约把路径、触发链和建议放在同一行，ledger 从首行截 200 字作标题，前端再截 120 字。新 Attempt / Aggregator 要求 16–32 字中文“关键条件 + 后果”短标题，完整细节及原 Finding ID 留在缩进正文，既有解析与身份算法不变。
- Grok 1.0.41 的空 tools allowlist 未移除内置读取和搜索工具。原真实失败在首 token 后继续多轮读取空工作目录并推理，最终 180 秒超时。解释专用调用明确禁用残留工具、单轮低推理，继续保留原 sandbox 和禁写限制；没有修改全局 Grok 配置。
- 原解释执行丢弃 failure / duration / activity，且没有清理临时认证目录。现分别报告超时、取消、启动失败、空输出；真实 runner 完成进程回收后才释放请求，成功失败均清理自身临时目录。
- 真实 Grok 输出存在“完整 JSON 对象后多一个闭合大括号”的情况。仅恢复这一确定格式，原输出保留并记录归一化标记；不接受尾随文字、第二对象、内部非法或未闭合数据，后续 schema 与冻结代码引用校验不变。

## 模型透明与标题展示

- 新增 session 只读 `explanation-agents` 接口，公开已有 Agent 名称、模型、驱动、可选状态及默认来源，不包含凭据或 persona。
- 默认仍是当前 `pr-jury` Reporter（缺 Council 才取 Run Aggregator 对应的当前 Agent 配置），页面在生成前显示实际选择，允许显式切换。失效的手动选择会保留并阻塞生成，不静默改用默认 Agent。
- GET / POST 显式携带 Agent，缓存按 Agent 与执行配置隔离。客户端提交所见模型/驱动，服务端在缓存读取及 spawn 前核对；变化时返回 `409 EXECUTION_CONFLICT`。客户端也核对结果 provenance 后才显示、缓存标题。
- 解释新增兼容的可选 `title`；历史问题成功生成或读取解释后，简明标题同步到详情与导航。未生成时保留原评审摘录。原 title / text / id / 决策断言不改写。
