# 0010: Discussion modes are carried by instruction templates only; blind review deferred

The three Discussion Modes (brainstorm / planning / review) are implemented as families of instruction templates (focus / message / summary / report) with zero orchestration branches: mode never changes execution, cursor, transaction, or snapshot rules. This keeps one code path for every mode and one digest semantics for every snapshot.

`docs/product.md` §4.3 asks reviewers to "review independently" (blind review — peers' reviews hidden to prevent anchoring). Our shared-context model makes anchoring structural: a later reviewer's snapshot includes earlier reviews, and no instruction wording can reliably prevent it. We accept this anchoring risk in the decision-core milestone and defer true blind review (per-participant snapshot filtering for review mode: reviewers see topic/background/user material + their own messages only; the facilitator sees everything at summary time) to a later, additive change. Alternatives rejected for this milestone: orchestration branches per mode (breaks the single-path design) and "half-blind" filtering that still leaks earlier reviews in the same round (no real benefit over accepting the risk).
